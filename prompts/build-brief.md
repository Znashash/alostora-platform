# Alostora — Build Brief & Decisions

## Scope

Build **only** the Alostora WordPress theme. Do **not** create plugins or rebuild Elementor,
LifterLMS or VdoCipher. Integrate cleanly with all four.

## Approved architecture + modifications

1. Primary Arabic font: **IBM Plex Sans Arabic** (body); Tajawal for display/headings.
2. Homepage built **entirely in the Elementor Pro Theme Builder** — no `front-page.php`.
3. Theme provides design system, components, styling and integrations only; homepage content stays
   editable in Elementor.
4. `template-parts/content` replaced by a **reusable components architecture**
   (`components/{header,footer,hero,buttons,course-card,statistics,video-card,step-card,testimonial}`).
5. **SCSS architecture** under `assets/scss` compiled to `assets/css`.
6. Elementor folders: `elementor/kits` and `elementor/theme-builder`.
7. Optimize for WebP/AVIF, lazy loading, font preloading, critical CSS and Core Web Vitals.
8. **Dark-mode-ready** structure (semantic CSS custom properties) without implementing it now.
9. LifterLMS template overrides + VdoCipher integration as proposed.
10. WordPress Coding Standards; production-ready; no placeholder code.

## Key implementation decisions

- Classic (Hello-style) theme + Elementor Theme Builder locations; templates fall back to
  components when no Elementor template is assigned.
- Design tokens in `theme.json`, surfaced as semantic custom properties for theming/dark mode.
- Self-hosted fonts split into Arabic + Latin subsets (generated by `scripts/fetch-fonts.js`).
- Build toolchain: dart-sass + PostCSS/autoprefixer + rtlcss (`theme/package.json`).

See [`../docs/architecture.md`](../docs/architecture.md) for the full design.
